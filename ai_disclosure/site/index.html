Say which AI wrote it

A simple practice for Open Source projects that accept contributions written with AI tools. Each commit names the model that wrote it, and a person answers for the change. Nothing more is needed to start: one line at the end of a commit, and a few sentences in the files a project already has.

The practice, in three sentences

Say so

A commit that was not written by a human ends with a trailer naming the model and its version.

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>

A human answers for it

Every change is read, understood and tested by the person who submits it, whoever or whatever wrote it. An agent does not open a pull request on its own.

No shame, no ranking

Declaring an AI tool is never held against a contribution. Nobody has to use one, and nobody has to explain why they do not.

What a project adds

The shortest way is one paragraph in CONTRIBUTING.md. The whole practice is a section in three files, ready to copy:

  • CONTRIBUTING.md, for people;
  • AGENTS.md, for AI agents, which then write the trailer themselves;
  • two boxes in the pull request template.

The same commitments exist as a short, versioned text, the AI transparency charter, that a project can adopt by name.

What it looks like in real projects

This site follows a few projects as examples. For each one it reads the commits and the pull requests, and shows what their contributors declare: which models are named, since when, and by how many people. The figures are a lower bound, and the pages rank nobody.

The list is a showcase, not a registry: it is kept short on purpose. To see the same pages for your own projects, run the tool yourself.

Run it for your own projects

The tool that builds these pages is free software, written in Python with the standard library only. It reads a list of repositories and writes a static site, which any web server can publish.

pip install git+https://github.com/cedricbonhomme/ai-disclosure
ai-disclosure build        # reads projects/, writes _site/

One small file per project says where the repository is and from which date its rule applies. The README explains the rest.

Not every project chooses this

Some projects refuse AI-generated contributions, others set no rule. This site takes no side on whether to use AI: it describes one way to be open about it. How other projects do it is compared on its own page.
